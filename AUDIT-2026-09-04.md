## 6. [HIGH] Read-modify-write race lets concurrent requests defeat account lockout

- **Status:** OPEN
- **Category:** Security
- **Effort:** M
- **Location:** `apps/api/src/services/auth.service.ts:237,262,305`

**Impact.** `failedLogins` is read once, then written back as an absolute value after the deliberately slow Argon2id verify. Concurrent attempts all read the same baseline and write the same result, so N parallel wrong-password requests move the counter from 0 to 1. The per-IP limiter bounds a single-source attacker, but the per-account lockout is the only account-level control and it is defeated by a distributed attempt.

**Recommended fix.** Make the increment atomic in SQL: `UPDATE users SET failed_logins = failed_logins + 1, locked_until = CASE WHEN failed_logins + 1 >= 5 THEN now() + interval '30 minutes' ELSE locked_until END WHERE id = $1 RETURNING failed_logins`, and drive the lockout decision off the returned value.

## 16. [MEDIUM] SSE stream skips the idle-timeout check every other route enforces

- **Status:** OPEN
- **Category:** Security
- **Effort:** S
- **Location:** `apps/api/src/routes/stream.routes.ts:44,60; apps/api/src/middleware/auth.middleware.ts:45`

**Impact.** `IDLE_TIMEOUT_MS` lives only in the auth middleware, which this route does not use — it calls Lucia directly on both credential paths. A session idle past the 7-day window still opens a live stream of the user's events and tasks.

**Recommended fix.** Extract `assertSessionFresh(session)` and call it from both validation paths, the way RepoVault shares `readValidSession`.

## 22. [MEDIUM] Session id is accepted as a URL query parameter

- **Status:** OPEN
- **Category:** Security
- **Effort:** M
- **Location:** `apps/api/src/routes/stream.routes.ts:14-16,58-60`

**Impact.** `token` is the raw Lucia session id travelling in the query string, where proxy logs, browser history and `Referer` record it. The app's own logger is clean (it records `c.req.path`), so the exposure is entirely in surrounding infrastructure.

**Recommended fix.** Issue a short-lived single-purpose SSE ticket (random id in Redis, 60s TTL, consumed on use) instead of the session id.

## 32. [LOW] Rate limiting fails open when Redis is unreachable

- **Status:** OPEN
- **Category:** Security
- **Effort:** M
- **Location:** `apps/api/src/middleware/rate-limit.middleware.ts:57-73`

**Impact.** Reasonable for ordinary reads, less so for `auth:login` and `auth:forgot-password`. Combined with finding 06, a Redis outage leaves no effective brute-force ceiling at all.

**Recommended fix.** Make the posture per-limiter: `failClosed: true` for the `auth:*` prefixes.
